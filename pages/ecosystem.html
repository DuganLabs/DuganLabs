What each product adds

Deliberately not a second copy of the Projects page: this is each product’s place in the ecosystem rather than its pitch.

  • BaseNative

    The foundation

    The signal-based runtime and the package library the rest of this page is about. It is the only product that is also infrastructure — when something here needs a capability twice, it ends up in BaseNative and the copy gets deleted.

    SiteSource

  • GreenPut

    Consent-mediated lead portability

    A lead belongs to the homeowner who created it, not to whoever bought it first. GreenPut moves leads between home-service contractors on the homeowner’s consent, with the CRM around it — jobs, estimates, invoices — as the reason anyone stays.

    SiteSource: private

  • PendingBusiness

    Personal treasury OS

    Tax withholding, float yield, bill timing and debt payoff as one optimisation rather than four apps. The hardest scheduling and money-movement problems in the ecosystem, which is why the primitives it needs tend to surface in BaseNative first.

    SiteSource: private

  • T4BS

    The stress test

    A word puzzle with poker mechanics — per-tile wagers, cascades, an all-in shove. It is the product with real-time state and animation budgets, so it is where the runtime’s rendering path gets found out.

    SiteSource

Shared conventions

The reason a package can move between these products without a port: they already agree on everything below.

Runtime
BaseNative signals. Function-call reactivity, SSR-aware, no framework underneath it.
Shared code
Lives in BaseNative and is consumed from there. Extracting something and leaving the original copy behind does not count.
Styling
Design tokens and plain CSS in cascade layers. No CSS framework, no inline style attributes, no per-page style blocks.
Delivery
Cloudflare Workers, with static assets served by the same Worker that renders the dynamic parts.
Secrets
Doppler, injected in the pipeline. Nothing secret is ever committed, and no project keeps its own store.
CI
Reusable workflows from the org’s .github repository, so a pipeline fix lands once for every project.
